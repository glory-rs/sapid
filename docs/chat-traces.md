# Trace, StackTrace, Tool and Subagent

The optional `chat` feature provides application-supplied execution records.
The components display public records and emit explicit callback requests. They
do not run tools, dispatch agents, open files, fetch URLs, inspect private
reasoning or derive status from a process. Applications supply status, elapsed
milliseconds, hierarchy and public input/output.

```rust
use sapid::chat::*;
let request = TraceKey::new("request")?;
let lookup = TraceKey::new("lookup")?;
let data = TraceData::new([
    TraceRecord::new(request.clone(), TraceKind::Span, "Application request")?
        .status(TraceStatus::Running),
    TraceRecord::new(lookup, TraceKind::Tool, "Lookup")?
        .parent(request)
        .input(TracePayload::Public(TraceText::new("Public arguments")?))
        .output(TracePayload::Redacted),
])?;
let widget = trace("request-log", data).on_action(|request| {
    // Application chooses whether to inspect this record.
});
```

`TraceData` is a sealed, finite forest. Its constructor accepts at most 256
records, depth 16 and 64 KiB of source text, including titles, keys, parent keys
and both public payloads. Input is consumed only through the 257th sentinel.
Duplicate complete keys, missing parents and cycles are rejected. Parents can
follow children in the supplied order; roots and siblings retain application
order. Current indices accelerate lookup and child traversal; removed keys do
not remain in a visited-record registry.

Keys are 1–64 ASCII bytes using letters, digits, `_`, `-`, `.`, `:`. Titles
are nonempty single-line text up to 256 bytes. Public payloads admit at most
8192 UTF-8 bytes and allow LF/tab while rejecting other control characters.
`TraceText::prefix(source, budget)` explicitly takes a UTF-8 codepoint-safe
prefix, never splits a codepoint and marks discarded text as `[truncated]`.
It does not promise grapheme segmentation or retain the suffix. `Redacted`
contains no original secret and displays `[redacted]`; applications must
classify/redact before construction. All markup and path text stays literal.
Elapsed time is optional, integer milliseconds, at most seven days; it is not
a running clock.

`trace(key, data)` uses a named Group, true nested ordered lists and independent
Collapsible buttons with stable trigger/panel relations. The namespace is
1–32 ASCII letters/digits/underscore/hyphen. Numeric, non-wrapping construction
tickets identify live disclosure shells without truncating business keys or
retaining a history. The same full key and parent preserve a mounted row when
title/status/payload changes. Moving a record to another parent or removing it
retires its row Owner. Empty forests display an explicit empty message.

Expansion uses `.expanded(Lotus<TraceExpansion>)` or local
`.default_expanded(...)`. `on_expand_change(TraceToggle)` proposes the key,
requested open state and finite expanded set. Controlled sources are read-only;
refusal preserves accepted UI. External source updates are silent. Local
expansion removes absent keys and does not reopen them on reinsertion.
Applications own pruning of an explicitly controlled expanded set. Unmount is
the default content policy; `.content_policy(ContentPolicy::KeepMounted)` keeps
hidden child state/tasks. Neither policy implies that a hidden tool is running.

Providing `on_action(TraceAction)` creates an actual, enabled Inspect button.
Without it the trace has no action button. `.action_label(...)` changes its
finite, single-line label. Typed callbacks run before matching generic Activate
observers. A typed callback that retires its origin suppresses its stale
observer. `.enabled(false)` disables actual disclosure/action buttons and gates
requests. Theme, size, class/style, name, focus, node_ref and unstyled follow
the common component contract. Public payloads remain bounded scroll regions
even in unstyled mode; `.payload_height(80..=640)` defaults to 240 px.

`tool(key, record)` and `subagent(key, record)` are standalone records using the
same renderer, each with `.open(...)`, `.default_open(...)`,
`.on_open_change(...)`, `.on_action(...)`, content policy and common options.
The record must have the corresponding kind and no parent. Invalid dynamic
kind/parent updates reject the complete update and retain the last admitted
record. A later valid value recovers. No callback is generated by this recovery.

## Stack locations

`StackTraceData::new(message, frames)` admits at most 128 frames and 64 KiB of
source text, with the same payload policies. It consumes only a 129th sentinel.
Frame keys are complete and unique. `StackFrame` requires a finite function
label; its optional `StackLocation` contains a literal file label up to 1024
bytes, a positive line and optional positive column. Coordinates are
application-provided display locations, not byte/UTF-16 indices. No parser,
filesystem URL inference, source-map lookup or ambient filesystem access is
performed.

`stack_trace(data)` renders a named Group, literal code message and a real
ordered list. Without `.on_location(...)`, locations are passive text. With
it, an actual Button proposes `StackLocationRequest { key, location }` using
the current accepted frame, before its generic Activate observer. Source
updates preserve same-key function/location control identity; removal retires
the frame. The control never opens or navigates by itself. Disabled gates the
real buttons. Empty stacks have an explicit empty state.
